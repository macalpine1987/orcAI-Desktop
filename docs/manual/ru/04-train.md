# Обучение

В разделе **Обучение** создаются собственные модели распознавания на основе ваших записей: с нуля или на основе готовой модели. Последовательность шагов совпадает с последовательностью команд orcAI в терминале.

Раздел доступен, если у активного проекта задана цель «Обучение модели» или «Полный цикл». При цели «Распознавание» пункт **Обучение** в боковом меню отображается, но недоступен.

> **Важно.** Обучение занимает много времени и места на диске: на обычном компьютере от нескольких часов до суток, подготовленные данные занимают десятки гигабайт. Окно приложения можно свернуть (на macOS также скрыть через ⌘W): обучение продолжится в фоне. На Windows для фона сверните окно — ✕ / Alt+F4 завершают приложение. При полном выходе из приложения обучение прерывается.

## Основные понятия

| Термин | Определение |
|--------|-------------|
| Аннотация | Ручная разметка записи: в каких интервалах слышен тот или иной звук. Модель обучается по аннотациям; чем больше качественной разметки, тем выше качество модели |
| Класс | Код звука в параметрах модели и файлах меток, например `WHISTLE` или `BUZZ`. Не путайте с типом — читаемым именем в таблице обнаружений (часто берётся из синонима метки) |
| Спектрограмма | Изображение звука: по горизонтали отложено время, по вертикали — частота. Модель обучается по спектрограммам, а не по исходной звуковой волне |
| Сниппет | Фрагмент спектрограммы фиксированной длительности (по умолчанию 4 с). Один сниппет — один обучающий пример |
| Выборки train / val / test | Три части набора сниппетов. Обучающая выборка (train) используется для обучения, проверочная (val) — для контроля хода обучения, тестовая (test) — для итоговой оценки качества. Проверочная и тестовая выборки не участвуют в обучении |
| Эпоха | Один полный цикл обучения |
| Батч | Группа сниппетов, обрабатываемая моделью за один шаг |

Полный словарь терминов приведён в главе «Глоссарий».

## Выбор способа обучения

| Задача | Инструмент |
|--------|------------|
| Обучить новую модель на своих данных | **Мастер обучения**, сценарий «Обучить модель с нуля» |
| Улучшить готовую модель или адаптировать её к другой популяции | **Мастер обучения**, сценарий «Дообучить существующую модель», либо кнопка **Дообучить** в разделе **Модели** |
| Повторить отдельный шаг или продолжить прерванную работу | Доска **Конвейер** |

Для первого обучения используйте мастер: он проверяет данные, подставляет рекомендуемые значения параметров и запускает все шаги в нужном порядке.

## Подготовка данных

Перед обучением убедитесь, что:

1. На странице **Главная** запущена среда выполнения.
2. В проекте есть WAV-записи и файлы аннотаций к ним: текстовые метки Audacity в папке `annotations/`. Имя файла аннотации должно совпадать с именем записи (`clip.wav` и `clip.txt`). Файлы `*_predicted.txt` и `*_predicted_filtered.txt` аннотациями не считаются.
3. Существует таблица записей `recording_table.csv`. Приложение создаёт её автоматически при добавлении записей.

> **Важно.** Пока в проекте нет ни одного файла аннотации с именем, совпадающим с именем записи (в том числе в проекте без WAV-файлов), кнопка **Мастер обучения** недоступна как в разделе **Проекты**, так и на доске **Конвейер**.

> **Для пользователей командной строки.** Шаг «Спектрограммы» завершается ошибкой, если в таблице записей нет подходящих строк: аннотации отсутствуют, а флаги `-en` / `-enp`, разрешающие обработку неразмеченных записей, в интерфейсе недоступны.

Если в аннотациях звуки подписаны иначе, чем называются классы модели (например, `Buzz3` вместо `BUZZ`), не переименовывайте файлы: задайте синонимы меток на втором шаге мастера. Мастер сохраняет их в файл `call_equivalences.json`. Без этого файла шаг `create-label-arrays` завершается ошибкой, как и команда orcAI без параметра `-ce`.

## Мастер обучения {#wizard}

Мастер состоит из пяти шагов. На любом шаге можно вернуться назад и изменить настройки.

### Шаг 1. Выбор сценария

- **Обучить модель с нуля.** Модель обучается только на ваших данных. Требуется большой объём размеченных записей.
- **Дообучить существующую модель.** Готовая модель уточняется на ваших данных. Сценарий подходит при небольшом объёме данных, так как предобученная модель быстрее адаптируется к новым записям. См. раздел «Дообучение».

### Шаг 2. Данные и классы

На шаге задаются:

- **Таблица записей** и **папка аннотаций** — приложение определяет их автоматически;
- **Классы модели** — коды звуков, которые модель будет распознавать. Для каждого класса отображается число примеров в аннотациях и число записей, в которых они встречаются. Если примеров очень мало, модель не сможет выучить класс; отключите такой класс или добавьте разметку;
- **Синонимы меток** — соответствие между подписями в аннотациях и классами модели. Например, если часть разметчиков использовала подпись `Buzz`, а часть — `Buzz3`, укажите, что обе подписи обозначают класс `BUZZ`.

Кнопка **Сохранить черновик** записывает выбранные настройки в файл параметров проекта.

### Шаг 3. Спектрограммы и сниппеты

Параметры шага определяют, как звук преобразуется в обучающие примеры. Значения по умолчанию взяты из orcAI и подходят для записей косаток. Изменяйте их только при наличии специальных требований.

> **Важно.** Параметры спектрограммы входят в состав обученной модели. Распознавание этой моделью возможно только для записей, обработанных с теми же параметрами.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Частота дискретизации | 48 000 Гц | Частота, к которой приводятся все записи |
| Размер окна (`nfft`) | 512 | Чем больше значение, тем точнее разрешение по частоте и тем ниже разрешение по времени |
| Шаг окна (`n_overlap`) | 256 | Сдвиг окна в отсчётах. Может превышать размер окна |
| Диапазон частот | 0–16 000 Гц | Часть частотного диапазона, которую анализирует модель |
| Квантили яркости | 0,01 и 0,999 | Границы нормировки яркости спектрограммы; ограничивают влияние слишком громких и слишком тихих участков |
| Длительность сниппета | 4 с | Длительность одного обучающего примера |
| Сниппетов в секунду | 3 | Частота нарезки примеров. Чем выше значение, тем больше примеров и тем больше места они занимают на диске |
| Длина сегмента | 200 с | Запись обрабатывается сегментами такой длительности |
| Доля пустых сниппетов | 0,99 | Доля сниппетов без меток, которая отбрасывается. В записях пустых фрагментов намного больше, чем звуков; без отбрасывания обучение шло бы преимущественно на них |
| Доли train / val / test | 0,8 / 0,1 / 0,1 | Распределение примеров между выборками. Сумма должна быть равна 1 |

> **Примечание.** Параметр называется `n_overlap` в файле параметров, но задаёт именно шаг окна (hop), а не величину перекрытия.

В нижней части шага отображается оценка: число получаемых сниппетов, объём спектрограмм на диске и ориентировочное время подготовки.

### Шаг 4. Модель и обучение

На шаге настраиваются нейронная сеть и процесс обучения. Значения по умолчанию соответствуют настройкам из публикации orcAI, на которых обучены встроенные модели. Для первого обучения их рекомендуется не изменять.

Кнопка **Вернуть значения** восстанавливает значения по умолчанию для всех параметров, кроме имени модели.

#### Основные параметры

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Имя модели | `orcai-model` | Имя папки, в которую сохраняется модель. Задайте осмысленное имя, например с указанием места и года записей |
| Архитектура | `ResNetLSTM` | Тип нейронной сети. `ResNetLSTM` лучше учитывает изменение звука во времени; `ResNet1DConv` проще и быстрее |
| Эпохи | 30 | Максимальное число эпох. Обучение может завершиться раньше, если качество перестало улучшаться |
| Размер батча | 64 | Число примеров, обрабатываемых за один шаг. При нехватке памяти уменьшите значение до 32 |
| Скорость обучения | `1e-4` | Величина изменения модели за один шаг. При слишком большом значении обучение становится нестабильным, при слишком малом — очень медленным |

#### Параметры архитектуры сети

Параметры изменяются редко.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Фильтры свёрток | 30, 40, 50, 60 | Число признаков, выделяемых на каждом уровне сети |
| Размер ядра (`kernel_size`) | 5 | Размер участка спектрограммы, обрабатываемого за один раз |
| Dropout | 0,3 | Доля нейронов, случайно отключаемых при обучении. Снижает риск переобучения, при котором модель запоминает примеры, а не обобщает закономерности |
| Размер слоя LSTM | 128 | Объём внутреннего состояния сети, учитывающего предыдущие моменты звука (только для `ResNetLSTM`) |
| Инициализаторы | `he_normal`, `glorot_uniform` | Способы задания начальных весов сети |

#### Управление ходом обучения

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Метрика мониторинга | `val_MBA` | Доля верных ответов на проверочной выборке; классы, не размеченные в записи, не учитываются. По этому показателю оценивается прогресс, сохраняется модель с лучшим значением |
| Ранняя остановка | 10 эпох | Обучение прекращается, если качество не растёт указанное число эпох подряд |
| Снижение скорости обучения | 3 эпохи, ×0,5 | Если качество не растёт 3 эпохи, скорость обучения уменьшается вдвое. Это позволяет точнее довести модель до оптимума |
| Минимальная скорость обучения | `1e-7` | Нижняя граница, до которой может снижаться скорость обучения |
| Веса классов | не заданы | Значение `balanced` придаёт больший вес редким классам. Используйте, если количество примеров разных классов сильно различается |
| Seed | 0 | Начальное значение генератора случайных чисел. При одинаковых данных и одинаковом значении результаты обучения воспроизводятся |

#### Количество батчей

Параметры `n_batch_train`, `n_batch_val` и `n_batch_test` задают число батчей, берущихся из каждой выборки за одну эпоху. Значения по умолчанию: 3750, 375 и 375.

Для каждой выборки требуется не менее `n_batch × размер батча` сниппетов. При значениях по умолчанию для обучающей выборки это 3750 × 64 = 240 000 сниппетов. Если сниппетов меньше, orcAI завершается с ошибкой. Чтобы избежать этого в orcAI Desktop, используются автоматическая коррекция и калькулятор сниппетов, описанные ниже.

#### Если сниппетов не хватает

orcAI сам не уменьшает число батчей под объём данных. Поэтому orcAI Desktop выполняет коррекцию перед запуском:

1. Перед разбиением на выборки и перед обучением приложение подсчитывает фактическое число сниппетов в обучающей, проверочной и тестовой выборках. Подсчёт выполняется так же, как в orcAI: после отбрасывания пустых фрагментов.
2. Для каждой выборки число сниппетов сравнивается с требуемым (`n_batch × размер батча`).
3. Если сниппетов меньше, число батчей уменьшается до наибольшего значения, которое помещается целиком: число сниппетов делится на размер батча с округлением вниз.
4. Скорректированные значения записываются во временную копию файла параметров, которую получает orcAI. Файл параметров проекта не изменяется.

**Пример.** Размер батча — 64; в параметрах задано 3750 обучающих батчей (требуется 240 000 сниппетов). После отбрасывания пустых фрагментов в обучающей выборке осталось 3400 сниппетов. Приложение установит 3400 ÷ 64 = 53 (остаток 8 отбрасывается), то есть 53 батча. Проверочная и тестовая выборки пересчитываются аналогично.

Если в какой-либо выборке сниппетов не хватает даже на один батч, уменьшать нечего, и orcAI завершается с ошибкой.

**Жёлтый индикатор «Сниппеты».** Индикатор сравнивает число сниппетов со значениями в параметрах проекта, а не со скорректированной копией. Жёлтый цвет означает, что в параметрах задано больше батчей, чем можно получить из имеющихся данных, и приложение уменьшило их число автоматически. Это не ошибка, однако в каждую эпоху модель получает меньше примеров, чем задано, поэтому эпохи получаются короче.

Чтобы индикатор стал зелёным, выполните одно из действий:

- задайте на шаге 4 число батчей из журнала задачи или меньшее (см. ниже);
- уменьшите размер батча;
- добавьте размеченные записи.

**Где посмотреть подставленные значения.** В разделе **Задачи** откройте задачу `create-tvt-snippet-tables` или `train` и перейдите на вкладку **Лог**. В журнале присутствует строка `Clamped n_batch_* to fit filtered snippet table` с новыми значениями, например `n_batch_train: 3750→53`.

**Калькулятор сниппетов.** Кнопка **Рассчитать…** рядом с полем «Батчей на эпоху» на шаге 4 открывает калькулятор. Он анализирует записи и аннотации проекта по той же схеме, что и orcAI, и для каждой выборки показывает:

- сколько сниппетов нарезано и в скольких из них есть звуки;
- сколько сниппетов остаётся после отбрасывания пустых фрагментов;
- сколько сниппетов требуется при текущих настройках;
- максимальное и рекомендуемое число батчей.

Если таблица сниппетов уже создана с теми же настройками, значения берутся из неё и являются точными. В противном случае калькулятор выдаёт оценку и рекомендует значение с запасом 10 %, так как orcAI выбирает фрагменты случайным образом. Кнопка **Применить рекомендуемые** подставляет значения в мастер. Калькулятор также предупреждает о записях короче одного сегмента: orcAI пропускает такие записи целиком.

### Шаг 5. Проверка и запуск

Мастер ещё раз проверяет настройки и показывает план: перечень шагов и порядок их выполнения. Доступны два варианта запуска:

- **Запустить обучение** — подготовка данных, обучение модели и оценка её качества на тестовой выборке;
- **Только подготовка данных** — подготовка без обучения. Используйте, чтобы заранее убедиться, что примеров достаточно.

Все шаги добавляются в раздел **Задачи** и выполняются по очереди.

### Нефильтрованный тест

На шаге 5 доступен флажок **Нефильтрованный тест (-tu)**. Он добавляет к стандартной проверке модели вторую — на данных, максимально близких к полевым записям.

При подготовке данных orcAI отбрасывает почти все фрагменты без меток (параметр «Доля пустых сниппетов» на шаге 3). В полевой записи пустых фрагментов значительно больше, чем звуков. Стандартный тест их исключает, поэтому оценка качества модели может оказаться завышенной по сравнению с реальным распознаванием.

Нефильтрованный тест использует фрагменты из тестовой части записей без такой очистки, вместе с пустыми. Он точнее показывает поведение модели при распознавании обычных записей, в первую очередь частоту ложных срабатываний.

При включённом флажке:

- при разбиении на выборки orcAI дополнительно создаёт нефильтрованный тестовый набор;
- после обучения модель проверяется на обоих наборах, результаты сохраняются отдельно.

Стандартный тест выполняется всегда; флажок добавляет второй. В соседнем поле можно указать размер нефильтрованного набора (`-n_uts`). Если поле пустое, используется значение orcAI: столько же сниппетов, сколько в обучающей таблице. Если тестовых фрагментов меньше, orcAI берёт все доступные и сообщает об этом в журнале задачи.

Подготовка и тест с этим флажком занимают заметно больше времени и дискового пространства. Включайте флажок, если модель будет применяться к длинным записям и нужна заблаговременная оценка числа ложных срабатываний. Для первого пробного обучения флажок можно не включать.

## Конвейер {#pipeline}

Доска **Конвейер** отображает восемь шагов обучения orcAI и состояние каждого из них. Состояние определяется по файлам в папке проекта: если вы удалите результат шага, доска покажет, что шаг нужно выполнить заново.

### Состояния шагов

| Состояние | Значение |
|-----------|----------|
| Не выполнено | Шаг ещё не запускался |
| В очереди / выполняется | Шаг ожидает очереди или выполняется |
| Готово | Результат создан; кнопка открывает папку с ним |
| Устарело | Данные или параметры изменились; шаг рекомендуется выполнить заново |
| Нет данных | Отсутствует результат предыдущего шага или файлы, необходимые для запуска |
| Ошибка | Шаг завершился с ошибкой; причина указана в журнале задачи |

### Шаги конвейера

| № | Шаг | Команда orcAI | Назначение |
|---|-----|---------------|------------|
| 1 | Спектрограммы | `create-spectrograms` | Преобразует записи в спектрограммы. Самый требовательный к дисковому пространству шаг |
| 2 | Массивы меток | `create-label-arrays` | Преобразует аннотации в разметку, понятную модели, с учётом синонимов меток |
| 3 | Таблица сниппетов | `create-snippet-table` | Определяет, из каких мест записей будут вырезаны обучающие примеры |
| 4 | TVT-таблицы | `create-tvt-snippet-tables` | Делит примеры на обучающую, проверочную и тестовую выборки (TVT — train / val / test). На этом шаге orcAI проверяет, достаточно ли примеров для заданного числа батчей |
| 5 | TVT-датасеты | `create-tvt-data` | Формирует данные, на которых обучается модель |
| 6 | Поиск гиперпараметров | `hpsearch` | Необязательный шаг (см. раздел «Поиск гиперпараметров») |
| 7 | Обучение | `train` | Обучение модели |
| 8 | Тест | `test` | Оценка качества на тестовой выборке |

Каждый шаг можно запустить отдельно, если выполнены предыдущие.

### Индикаторы готовности данных

Слева на доске расположено несколько индикаторов. Два из них относятся к разметке.

**Аннотации.**

- Зелёный: найдена хотя бы одна аннотация с именем, совпадающим с именем WAV-файла.
- Жёлтый с подписью «0 из N»: таких файлов нет (N — число загруженных WAV-файлов). Пока индикатор жёлтый, мастер и все шаги, начиная с «Массивов меток», не запускаются. Шаг «Спектрограммы» при пустом наборе подходящих строк завершается ошибкой (см. раздел «Подготовка данных»).

**Записи без аннотаций.**

- Зелёный: у каждого WAV-файла есть парный `.txt`.
- Жёлтый: указывает число записей, которые будут пропущены, то есть WAV-файлов без парного файла разметки. Если размечена хотя бы одна запись, шаги конвейера можно запускать; записи без `.txt` в обучение не включаются.

## Поиск гиперпараметров {#hpsearch}

Гиперпараметры — настройки архитектуры сети: число фильтров, размер ядра, dropout, размер слоя LSTM. Поиск гиперпараметров перебирает сочетания значений и выбирает то, при котором модель обучается лучше всего.

Поиск занимает много времени, часто больше, чем само обучение. Для первого обучения он не нужен: значения по умолчанию подобраны авторами orcAI.

Запустить поиск можно двумя способами:

- на шаге 5 мастера («Проверка и запуск») включить **Подобрать гиперпараметры** при обучении с нуля;
- выполнить шаг «Поиск гиперпараметров» на доске конвейера.

Найденные значения используются при обучении только если это выбрано в мастере. Параметры проекта при этом не изменяются.

Поиск выполняется последовательно. Флаг параллельного поиска на нескольких GPU (`-pl`) в интерфейсе Desktop скрыт; при необходимости его можно передать через CLI orcAI.

## Дообучение {#finetune}

При дообучении модель не обучается с нуля, а продолжает обучение на основе готовой модели. Так, исландскую модель `orcai-isl-v1` можно адаптировать к записям косаток из другого региона. Именно таким образом получена норвежская модель `orcai-nor-v1`.

Не подлежат изменению параметры, заложенные в исходную модель:

- набор классов и архитектура сети;
- параметры спектрограммы и длительность сниппета.

Можно изменить: имя новой модели, число эпох, скорость обучения, число батчей, веса классов, а также данные и синонимы меток.

Мастер показывает, сколько новых примеров имеется для каждого класса исходной модели. Если для класса примеров нет, он остаётся в модели, но не улучшается. Модель, не имеющая ни одного общего класса с аннотациями проекта, остаётся в списке, но выбрать её нельзя.

> **Важно.** Задайте новой модели имя, отличное от имени исходной. Иначе папка исходной модели будет перезаписана.

## Монитор обучения {#monitor}

Кнопка **Монитор** на доске конвейера становится доступной с началом шага «Обучение» и остаётся доступной, если сохранён снимок предыдущего запуска. Пока идёт обучение, на кнопке горит зелёный индикатор; до старта шага и после остановки индикатор не горит.

Монитор открывается в отдельном окне, независимом от главного. Главное окно можно свернуть или скрыть (на macOS — кнопкой закрытия или ⌘W; на Windows — свернуть в панели задач). Окно монитора остаётся на рабочем столе. Закрытие окна монитора обучение не останавливает. Полный выход из приложения (на macOS — ⌘Q; на Windows — ✕ / Alt+F4 у главного окна или выход из меню) останавливает среду выполнения и прерывает обучение.

Во время обучения монитор показывает:

- номер текущей эпохи и прогресс внутри неё;
- основные показатели качества;
- график изменения показателей по эпохам.

Рост показателей на проверочной выборке свидетельствует о том, что модель обучается. Если показатели перестали расти, скорость обучения автоматически снижается, а затем обучение останавливается.

Кнопка **Остановить** прерывает обучение. Лучшая из сохранённых к этому моменту моделей остаётся на диске. Кнопка **Открыть папку** открывает папку с файлами модели.

## Место на диске

Спектрограммы и подготовленные данные могут занимать десятки гигабайт. Перед ресурсоёмкими шагами приложение оценивает наличие свободного места и выводит предупреждение, если его недостаточно. В этом случае удалите ненужные результаты на вкладке **Проекты → Артефакты** или перенесите проект на другой диск.

## Краткая памятка

1. Запустите среду выполнения на странице **Главная**.
2. Убедитесь, что в проекте есть записи и аннотации.
3. Откройте мастер и выберите сценарий «Обучить модель с нуля» или «Дообучить существующую модель».
4. Отметьте классы и, если нужно, задайте синонимы меток.
5. На шагах 3 и 4 оставьте значения по умолчанию. Число батчей при нехватке сниппетов приложение скорректирует автоматически (см. раздел «Если сниппетов не хватает»).
6. Запустите обучение и контролируйте его в мониторе.
7. После завершения оцените модель в разделе **Модели** и назначьте её для распознавания.
