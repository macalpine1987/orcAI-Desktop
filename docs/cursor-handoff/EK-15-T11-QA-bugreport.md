## Дефекты

### M-01 · Critical / Major — «Дообучить» не выполняет критерий П-11

**Шаги:** Модели → выбрать любую модель → **Дообучить**.  
**Факт:** открывается мастер на шаге сценария с `scenario=finetune` и `finetuneBaseModel`, но:

- `canNext()` возвращает `false` для finetune на шаге scenario;
- запуск / «Далее» режется `wizard.scenarioSoon`.

**Ожидание (П-11):** «Дообучить из карточки открывает мастер сразу в режиме дообучения этой модели» — готовность сценария.  
**Фактически:** deep-link есть, **прогон дообучения недоступен** (отложено на ЭК-16).  
**Риск:** в `T-11-protocol.md` A-05 помечен Pass по code — для приёмки UC это **ложный Pass**.  
**Где:** `ModelsPage.onFinetune`, `TrainWizard.tsx` (`canNext`, `launchBlockedReason`, `scenarioSoon`).

---

### M-02 · Major — Регресс описания orcai-nor-v1 (A-02)

**Факт:** RU/EN `models.builtinDesc.orcai-nor-v1` больше **не** говорит о дообучении isl на **30 эпохах**.  
Текущий RU: «адаптация orcai-isl-v1 под акустические особенности…».  
**Ожидание:** П-11 / A-02 — nor = isl, дообученная на норвежских данных 30 эпох.  
**Причина:** правка текстов под crop макета без сохранения критерия A-02.  
**Где:** `apps/ui/public/locales/{ru,en}/*.json` → `models.builtinDesc`.

---

### M-03 · Major — Карточка не показывает спектрограмму / форму входа

**Ожидание (П-11 п.2):** в карточке — классы, **параметры спектрограммы**, **форма входа**, размер.  
**Факт:** UI показывает имя, путь, файлы, KPI теста, F1-бары.  
`detail.spectrogram` / `detail.shape` / `architecture` с sidecar **приходят, но в `ModelsStudio` не рендерятся**.  
**Где:** `get_model_detail` vs `ModelsStudio.tsx`.

---

### M-04 · Medium — Разбивка по классам без точности/полноты

**Ожидание (П-11 п.3):** по классам — точность, полнота, F1.  
**Факт:** в строках классов только F1 (+ цветной бар). PR/RE есть в данных `test.classes`, но не выводятся.  
Макро PR/RE есть только в KPI сверху.

---

### M-05 · Medium — «Тест» без проверки готовности данных

**Шаги:** trained-модель, нет/`пустой` `tvt_data` или нет `*_orcai_parameter.json`.  
**Факт:** job `test` всё равно ставится в очередь → падение в Задачах.  
**Ожидание:** preflight / понятный отказ до `createJob` (как на конвейере).

---

### M-06 · Medium — Ошибки Import/Export/Detail — сырой JSON FastAPI

**Факт:** `res.text()` кладётся в `Error` / баннер. Пользователь видит `{"detail":"…"}` вместо локализованной фразы.  
**Где:** `api/models.ts` (`importModelDirectory`, `exportModelDirectory`, `fetchModelDetail`).

---

### M-07 · Medium — После «Тест» нет явной обратной связи

**Факт:** `trackJobInLab(job)` без навигации на `/jobs` и без toast «задача создана».  
Зависимость от того, заметит ли пользователь консоль/док.  
**Риск:** кажется, что кнопка «ничего не сделала».

---

### M-08 · Minor — «Открыть папку» для встроенных моделей

**Факт:** кнопка активна и для builtin; путь — каталог внутри bundled `orcai.models`.  
**Риск:** путаница / «зачем открывать системный бандл»; на части сборок reveal может быть неочевидным.  
**Предложение:** disable + tooltip «только модели проекта» **или** копировать в экспорт вместо reveal.

---

### M-09 · Minor — Compat при отсутствии project parameter

**Факт:** `compare_compatibility` → `checked: false`, `ok: true`, reason `no_project_parameter`.  
**Использовать** проходит без предупреждения.  
**Риск:** назначение модели в проект без параметров = «тихо ок», хотя сравнить нечего.

---

### M-10 · Minor / UX — «Выбрать» vs «Использовать»

**Факт:** «Выбрать» = фокус строки; «Использовать» = assign + Predict.  
В макете и в речи пользователей «выбрать модель» часто = сделать активной.  
**Предложение:** переименовать link в «Карточка» / убрать link (остаётся клик по строке) + усилить подпись primary.

---

### M-11 · Minor — Экспорт не отражён в протоколе Т-11

**Факт:** кнопка **Экспорт** (замена **Обучить**) реализована и покрыта code gate частично; в `T-11-protocol.md` / П-11 исходном списке нет.  
Не дефект продукта, а **дыра в чеклисте приёмки** — добавить A-08.
